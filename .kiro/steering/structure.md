# Project structure

```
VERIFIED-RAG-CITATIONS/
├── blockchain/                Hardhat 3 project (TypeScript, ESM)
│   ├── package.json
│   ├── hardhat.config.ts
│   ├── contracts/CorpusRegistry.sol
│   ├── test/CorpusRegistry.test.ts
│   ├── test/MerkleFixture.test.ts
│   └── test/fixtures/merkle.json   generated by Python, committed
├── vrag/                      Python package
│   ├── config.py              settings from .env (network, RPC, chain ID, LLM providers)
│   ├── text.py                text normalization + content hashing
│   ├── merkle.py              leaf hashing, tree building, proofs
│   ├── ingest.py              PDF/TXT → passages
│   ├── store.py               corpus files (public JSON) + private SQLite
│   ├── index.py               embeddings (local MiniLM) + Chroma search
│   ├── chain.py               web3 connection, chain ID check, deploy, publish, verify
│   ├── rag.py                 retrieve → prompt → parse citations → attach proofs
│   ├── verify.py              citation checks (on-chain proof + quote check)
│   └── cli.py                 `python -m vrag <command>`
├── app/streamlit_app.py       web app
├── tests/                     pytest tests
├── data/
│   ├── samples/               small sample docs committed to the repo
│   ├── public/                user's public PDFs (gitignored)
│   └── private/               user's private docs (gitignored)
├── out/                       generated corpora, Chroma DB, private.db (gitignored)
├── .env.example
└── requirements.txt
```

## Conventions
- Python: type hints on public functions, small modules, no global state except config.
- Use `pathlib.Path` for all file paths so the code works on Windows.
- Each CLI command lives in `vrag/cli.py` and calls functions from the other modules.
- Corpus IDs are the numeric IDs returned by `CorpusRegistry.publish`. Each corpus also
  has a human-readable slug (for example `gaa-2026`) used for local file names.
- Passage IDs shown to users have the form `<slug>:<docId>:p<page>:<index>`.
